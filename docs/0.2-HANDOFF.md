### 今天的性能实测（320×480，SPI 80 MHz，240 MHz）

- 整屏重绘 63–74 ms；空白屏 30–31 ms。
- `slide` 跟手吸附：440–470 ms，约 15 fps（每帧重绘两页）。
- 快照过渡：`fade` 210–270 ms、`stack` 290–335 ms、`zoom` 260–365 ms、`flip` 200–305 ms、`rotate` 325–390 ms。
- 数据 apply：7 组件约 1.0 ms，13–15 组件约 1.5 ms，25 组件约 2.1 ms。
- 固件 1.86 MB / 4 MB 分区，剩余约 2.25 MB；7 种动画代码合计 <2 KB。
- 每次过渡使用 1 张 RGB565 截图（约 307 KB PSRAM），结束后释放。

## 2. 换电脑后第一步

### 2.1 克隆与路径

```bash
git clone https://github.com/LAZTUDIO/esp32-llm-dashboard.git
cd esp32-llm-dashboard
git checkout feature/0.2-server
```

**仓库路径必须是纯 ASCII**。含「微雪」等中文的路径会让 ESP-IDF 的 include 路径乱码，报 `sdkconfig.h: No such file or directory`。

### 2.2 ESP-IDF（固件）

已验证版本：**ESP-IDF 5.5.5**。安装后，在 **PowerShell** 中激活（不要从 Git Bash 直接跑，会被判成 MSYS 并拒绝）：

```powershell
Remove-Item Env:MSYSTEM -ErrorAction SilentlyContinue
$env:PYTHONUTF8 = "1"
$env:IDF_TOOLS_PATH = "C:\Espressif"                      # 按新电脑实际路径改
$env:IDF_PYTHON_ENV_PATH = "C:\Espressif\python_env\idf5.5_py3.11_env"
. C:\Espressif\frameworks\esp-idf-v5.5.5\export.ps1
cd D:\path\to\esp32-llm-dashboard\firmware
idf.py build
idf.py -p COMx flash          # COM 号按新电脑设备管理器
idf.py -p COMx monitor        # 115200
```

- 板子有两个串口：原生 USB-Serial/JTAG（用于烧录/日志）和板载 USB-UART（CH343）。优先用原生口。
- **每次打开原生串口都会复位开发板**；串口测试命令要在一个会话里连续发完。
- `firmware/sdkconfig`、`build/`、`managed_components/` 都在 `.gitignore` 里，`idf.py build` 会自动生成/拉取。

### 2.3 服务端

```powershell
cd server
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy config.example.json config.json
notepad config.json
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8080
```

`config.json` 示例内容：

```json
{
  "panel_url": "http://106.13.206.148:8800",
  "panel_interval_s": 1.0,
  "panel_timeout_s": 4.0,
  "enable_system": true,
  "system_interval_s": 2.0,
  "enable_gpu": false,
  "gpu_interval_s": 5.0,
  "host": "0.0.0.0",
  "port": 8080
}
```

`panel_url` 是公开的 halogen-panel 状态接口，无需密钥。`server/config.json` 和 `server/data/layouts/` 被 git 忽略，不会跟着仓库走。

编辑器：`http://<新电脑局域网IP>:8080/editor/`  
健康检查：`http://<IP>:8080/api/v1/health`

### 2.4 导入今天的布局

```powershell
mkdir server\data\layouts -Force
copy examples\layout-320x480.json server\data\layouts\320x480.json
```

或在服务启动后：

```powershell
curl.exe -X PUT http://127.0.0.1:8080/api/v1/layout `
  -H "Content-Type: application/json" `
  --data-binary "@examples/layout-320x480.json"
```

这是今天的 2 页 13 组件布局（第 1 页 8 个、副本页 5 个），`page_animation = slide`。

### 2.5 设备配置（不随仓库走）

- Wi-Fi 名称/密码保存在设备 NVS，**不在仓库里**。换网络请长按 BOOT 3 秒进入配网：热点 `ESP32-LLM-Setup` / 密码 `llm123456`，浏览器打开 `http://192.168.4.1`。
- Dashboard 地址也保存在 NVS（旧电脑是 `http://10.168.1.116:8080`，新电脑 IP 会变）：
  - 配网页的 Dashboard 字段填 `http://<新电脑IP>:8080`，保存后设备重启；或
  - 串口执行 `d http://<新电脑IP>:8080`（`d -` 清空，设备会重新进入配网）。
- 传统 API 地址用串口 `c http://<API机器IP>:8731|<key>` 配置；与 Server 地址可以是同一台或两台电脑。
- 设备当前 IP、RSSI 等可用串口 `h` 查看。

`?` 看帮助。常用：

| 命令 | 作用 |
| --- | --- |

## 4. 今天修复/实现的内容

1. **Sparkline 曲线不可见**：`make_row` 高度用了 LVGL 默认 130px，把 KPI 副标签和曲线挤出卡片。改为 `LV_SIZE_CONTENT`，曲线现在有自动量程、首点铺满。
2. **长数值 KPI 截断**：数值超过 5 个字符自动换 24px 字体。
3. **翻页动画**：
   - `slide` 保留 LVGL 原生 tileview 滚动（跟手、松手吸附，约 15 fps）。
   - 其余效果关闭原生滚动；松手时按水平位移（>50px 且 `|dx| > 2|dy|`）判定，再用一张 PSRAM 截图做不透明变换，结束删除，低帧率无重影。
   - **坑**：`lv_tileview_add_tile()` / `lv_tileview_set_tile_by_index()` 会重置 `scroll_dir`；必须在添加完 tile 后、每次切页后再设 `LV_DIR_NONE`，否则触摸会绕过所有动画。
   - `flip` 必须显式 `lv_image_set_pivot(160, 240)`，否则会压到屏幕左边。
4. **原子换屏**：≤10 组件且内部 RAM >50KB 时，先建新屏再切换、最后删旧屏，构建期间旧界面保持可见；超过则退回先删后建（会短暂黑屏）。见 `ui_dynamic_commit()`。
5. **开机拉布局时序**：原来关联上 Wi-Fi 就拉，DHCP 还没拿到 IP，必然失败走缓存；现在等 `wifi_mgr_sta_ip()`。
6. **缓存过期**：WS 连接/重连后主动重拉；用 FNV 哈希跳过内容相同的重建。
7. **WS/控制台启动失败**：25 组件时内部最大连续块仅 3.4KB，WS 任务栈 8KB 起不来；WS 栈降到 6KB，服务端总组件上限从 64 降到 20。
8. **调试台栈溢出**：`b/B/C` 全屏渲染在 8KB 控制台栈上会重启；改为按需创建 PSRAM 栈的 `dbgperf` 任务。
9. **编辑器防覆盖**：收到 `layout_changed` 时，未修改自动重载；有未保存修改提示先点「重载」；保存后 2 秒内忽略自己触发的广播。

### 今天的布局覆盖事故（提醒）

测试脚本曾把用户在编辑器里保存的 2 页布局覆盖成旧备份。后来从设备 SPIFFS 分区（flash `0x420000`，1MB）原始 dump 中按 SPIFFS 页头（5B 头 + 251B 数据，256B/页）跳过空洞页，恢复了最新版布局。

**教训**：`server/data/layouts/` 是运行时数据、不在 git；批量测试前先备份，或先确认编辑器没有未保存修改。当前布局已导出到 `examples/layout-320x480.json`。

## 5. 已知限制

- **组件上限 20**：内部 RAM 碎片化，25 组件时最大连续块 3.4KB，WS 断线重建会失败。
- **原子换屏只覆盖 ≤10 组件**；更大的布局热更新仍有 200–500ms 黑屏。
- **字体固定 498 个 CJK 字形**：动态看板模式已由服务端字体子集解决；无字体时回退内置子集
- **配色只在 Web 配置**：设备端不保存主题，`theme_tokens` 必须由服务端 resolved 布局下发。
- **两路数据同 ID 冲突**：直连 API 与 Server WS 写同一 store，同 ID 以最后写入为准；跨机监控建议 API 用 `llm.*`/`host.*`，Server 本机用 `server.*`。
- **480×320 横屏**未实现；服务端已有 profile 入口但固件只接受 `320x480`。
- `slide` 跟手但只有约 15 fps；复杂效果 200–390ms，帧数少。`cube` / `carousel` 未实现，真 page curl 在 LVGL 上没有网格变形，只能做折页近似。
- 服务端/编辑器没有鉴权，默认只应在局域网使用。
- OTA 未做；当前 4MB app 分区 + 1MB SPIFFS，OTA 双槽空间紧张。
